# IMEST

Система тестирования на Django: кабинеты учителя и ученика, уникальные коды тестов,
индивидуальные попытки, автосохранение и серверный подсчёт результатов.

## Быстрый запуск в Windows

Из папки, в которой находится manage.py:

```powershell
./start.ps1
```

Если PowerShell запрещает запуск сценариев, используйте команды напрямую:

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
./.venv/Scripts/python.exe manage.py migrate
./.venv/Scripts/python.exe manage.py runserver 127.0.0.1:8000
```

Откройте http://127.0.0.1:8000/ и зарегистрируйтесь. Самостоятельная регистрация доступна только ученикам.
Администратор создаёт учителя в /admin/ → Teachers → Add: логин, имя, школа и пароль.
Для первого администратора выполните `python manage.py createsuperuser`. Роль учителя не даёт доступа к Django Admin или чужим тестам.

Проверено на Python 3.14.7, Django 5.2.17 и DRF 3.18.1. CI использует Python 3.13.
Зависимости находятся в requirements.txt. Внешние CDN, шрифты и npm для приложения не нужны.

## Учителю

1. Получите логин и пароль у администратора и войдите в кабинет.
2. Создайте тест: название, класс (необязательно), дату начала и длительность 1–480 минут.
3. Добавьте 1–100 вопросов. У каждого 2–8 различных вариантов и ровно один правильный.
4. Сохраните черновик. При сохранении автоматически создаётся уникальный код.
5. Проверьте предпросмотр, опубликуйте тест и передайте код ученикам.
6. Смотрите результаты и экспортируйте их в CSV, совместимый с Excel.

После публикации вопросы нельзя изменять. Для новой редакции создайте копию:
у неё будут новый код и независимые попытки. Архив закрывает вход новым участникам;
ученики с уже начатой попыткой могут её завершить. Физическое удаление через пользовательский API отсутствует.

## Ученику

1. Зарегистрируйтесь с тем же названием школы и обозначением класса, что у учителя.
2. Введите код, проверьте название, длительность и дату начала.
3. Начните попытку. Одна попытка на одного ученика в каждом тесте.
4. Выбирайте ответы и перемещайтесь между вопросами. Статус «Сохранено» означает
   подтверждение сервера, а не только сохранение в браузере.
5. Завершите тест и получите результат. За правильный ответ начисляется заданное учителем число баллов (1–1000), за ошибку или пропуск — 0.

Имя, школу и класс можно исправить в профиле. Школа и класс — самостоятельно
указанные реквизиты, а не подтверждённое членство в организации. Перед использованием
для экзаменов с формальным контролем доступа потребуется утверждение участников
администратором или список приглашённых. Знание кода само по себе не открывает чужие результаты.

## Уникальные коды

- 12 случайных символов из алфавита без I, O, 0 и 1.
- Поиск не зависит от регистра; пробелы и дефисы игнорируются.
- Код не является порядковым номером записи и не раскрывает число тестов.
- UNIQUE-ограничение базы и повтор генерации при коллизии.
- Код остаётся тем же при редактировании черновика.
- Копия получает новый код. Черновики и архивные тесты не находятся учениками.
- Ограничение поиска/старта: 30 запросов в минуту на пользователя.

## Надёжность результатов

TestAttempt хранит ученика, время начала, дедлайн, ответы, итог и неизменяемый
снимок вопросов с ключом оценивания. Правильные варианты не передаются ученику.

Дедлайн вычисляется сервером. Закрытие страницы и перезагрузка не продлевают время.
Просроченные попытки завершаются при обращении к API, кабинету или результатам.
Для завершения без посещения сайта предусмотрена команда:

```powershell
./.venv/Scripts/python.exe manage.py expire_attempts
```

На сервере её можно запускать планировщиком раз в минуту.

После дедлайна сервер оценивает только ответы, которые были сохранены до дедлайна.
Несохранённые ответы из офлайн-браузера после истечения времени не принимаются.

Запись ответов атомарна. Каждый запрос содержит ревизию; устаревшая вкладка получает
409 и не затирает более новые ответы. Повторное завершение возвращает исходный итог.
SQLite-транзакции используют IMMEDIATE, чтобы избежать гонки при повышении блокировки.

При потере сети браузер сохраняет неподтверждённую копию локально, если хранилище
доступно. При восстановлении связи отправка повторяется. При конфликте вкладок
пользователь явно выбирает загрузку серверной версии; скрытого перезаписывания нет.

## Проверки

```powershell
./.venv/Scripts/python.exe manage.py check
./.venv/Scripts/python.exe manage.py makemigrations --check --dry-run
./.venv/Scripts/python.exe manage.py test --noinput
./.venv/Scripts/python.exe scripts/verify_concurrency.py
node --check static/app.js
node --check static/editor.js
node --check static/room.js
```

Серверные тесты покрывают роли, права, CSRF, уникальность кодов, коллизии,
валидность вопросов, подсчёт, дубликаты, таймер, повторную отправку,
конфликты ревизий, миграцию старых записей, архив и CSV.
Проверка конкуренции создаёт отдельную временную SQLite-базу:
20 параллельных учеников, 8 конкурирующих стартов и 8 конкурирующих сохранений.
Временная база остаётся по пути, который печатает сценарий, для диагностики.

Это локальная проверка конкурентности, а не подтверждённая вместимость production-сервера.

## База и обновление старого проекта

Перед обновлением исходной базы создана копия в backups/before-upgrade-*.sqlite3.
Миграция 0002:
- сохраняет старые модели и записи ответов;
- назначает разный код каждому существующему тесту;
- переводит завершённые тесты и тесты с историческими ответами в архив;
- оставляет остальные старые тесты черновиками для проверки перед публикацией;
- нормализует старую длительность в диапазон 1–480 минут;
- добавляет необязательную связь старых учеников с User, не угадывая соответствие.

Старые StudentAnswer доступны администратору отдельно. Они не превращаются автоматически
в новые попытки, поскольку в исходной схеме нет надёжных данных о начале и дедлайне.

Для пользователя без профиля первый вход создаёт профиль ученика. Чтобы назначить
существующий аккаунт учителем, администратор создаёт Teacher со ссылкой на этот User.

## Резервное копирование

```powershell
./.venv/Scripts/python.exe manage.py backup_db
```

Команда делает согласованную SQLite-копию через backup API и проверяет её целостность.
Папка backups исключена из Git. Копии следует дополнительно хранить на отдельном носителе.
Для восстановления остановите приложение, сохраните текущую базу отдельно, скопируйте
выбранную резервную копию в путь DJANGO_DB_PATH (по умолчанию db.sqlite3), затем выполните
проверку миграций. Для копии до обновления примените migrate.

## Настройки сервера

.env.example — образец переменных; файл .env автоматически не загружается.

При локальном запуске случайный ключ создаётся один раз в .local-secret.
Этот файл, база, сессии, виртуальное окружение и копии исключены из Git.

Перед публикацией:
- DJANGO_DEBUG=false;
- DJANGO_SECRET_KEY — отдельный длинный случайный секрет;
- DJANGO_ALLOWED_HOSTS — реальные домены;
- DJANGO_CSRF_TRUSTED_ORIGINS — HTTPS-адреса;
- REDIS_URL — общее хранилище ограничений запросов для нескольких процессов;
- HTTPS, обслуживание staticfiles и резервные копии на стороне инфраструктуры.

В production включаются secure cookies, HTTPS redirect и HSTS.
Проверка --deploy оставляет W021: HSTS preload намеренно выключен до решения
владельца домена о включении в браузерные списки.
Не выставляйте сайт по HTTP с DJANGO_DEBUG=false: вход требует защищённых cookies.

```powershell
./.venv/Scripts/python.exe manage.py collectstatic --noinput
./.venv/Scripts/python.exe manage.py check --deploy
./.venv/Scripts/waitress-serve.exe --listen=127.0.0.1:8000 imest_project.wsgi:application
```

Waitress нужно размещать за HTTPS reverse proxy. Настройка доверенных заголовков
прокси зависит от конкретной инфраструктуры; не доверяйте заголовкам произвольных клиентов.
runserver предназначен только для разработки. Django пишет ошибки в stderr:
сбор логов, проверку доступности и уведомления настраивают в среде размещения.

Для большого числа одновременных участников следует отдельно подготовить PostgreSQL,
общий cache и нагрузочные тесты на целевом сервере.

## Дальнейшие расширения

Текущая версия реализует основной путь создания и прохождения теста. Отдельными
этапами остаются подтверждение членства в школе, восстановление пароля через почту,
переключение RU/UZ, импорт и банк вопросов, изображения/формулы, настраиваемые повторные
попытки, отложенная публикация разбора и расширенная аналитика.

## Рейтинг и режим тестирования

Публичный рейтинг `/rating/` (также главная страница для гостей) автоматически суммирует баллы завершённых попыток активных учеников. Равные суммы дают одинаковые места. Незавершённые попытки не учитываются; просроченные завершаются сервером при открытии рейтинга. Для регулярного завершения без посещений запускайте команду `expire_attempts` по расписанию. Разные тесты могут иметь разный максимум: рейтинг показывает накопленные баллы, а не процент успеваемости.

Баллы каждого вопроса сохраняются в неизменяемом снимке попытки; старые снимки без поля points оцениваются по 1 баллу. Процент результата считается от максимальной суммы баллов.

Вопросы отображаются после входа в полный экран. При потере фокуса, скрытии вкладки или выходе из полного экрана вопросы скрываются до возвращения. Есть предупреждение о закрытии и блокировка перехватываемых сочетаний клавиш/контекстного меню. События отправляются серверу с проверкой владельца, видны учителю в результатах и не меняют оценку автоматически. Доставка событий при закрытии или потере сети не гарантируется; потеря фокуса может иметь обычные причины. Это сигнал для проверки, а не доказательство списывания.

Обычный сайт не может запретить DevTools, новые окна, системные команды или закрытие браузера. Контроль на JavaScript можно обойти; правильные ответы не передаются ученику, оценивание работает на сервере. Для строгого ограничения нужен отдельно настроенный управляемый экзаменационный браузер/киоск. Для текущего режима нужен браузер с Fullscreen API; об этом ученик предупреждается до старта.

Во время прохождения ученик не видит стоимость вопросов: API исключает points из вопросов и скрывает максимальную сумму до завершения. Итоговые баллы и процент показываются после сдачи.
